# BladeFly 2P 测试指南

## 1. 测试目标
- 验证房间加入流程可用。
- 验证加入后显示房间名与角色信息。
- 验证“退出房间”按钮可见且可用。
- 验证基础对战流程（准备、读条、打断、胜负）正常。

## 2. 测试前准备
- 启动 WS 服务：
```powershell
node ws_server.js
```
- 浏览器打开 `TwoPlayers.html`。
- 建议准备两个浏览器窗口（或一个普通窗口 + 一个无痕窗口）模拟两名玩家。

## 3. 功能测试用例

### 用例 A：加入房间
1. 在“加入房间”输入框输入 `room_test_001`。
2. 点击“加入”。
3. 预期结果：
- 加入面板隐藏。
- 出现“已进入房间”面板。
- 显示房间名 `room_test_001`。
- 显示角色（A/B/旁观之一）。

### 用例 B：退出房间
1. 在已进入房间状态下点击“退出房间”。
2. 预期结果：
- 返回“加入房间”面板。
- “已进入房间”面板隐藏。
- WS 状态回到断开。

### 用例 C：双端同房对战
1. 两个窗口都加入同一房间（例如 `room_test_002`）。
2. 两边点击空白区域准备。
3. 预期结果：
- 进入准备倒计时（3 秒）。
- 进入 RUNNING 后可正常操作：A 长按读条，B 短按打断。
- 胜负文字与音效正常出现。

### 用例 D：房间切换
1. 先加入 `room_test_003`。
2. 点击“退出房间”。
3. 再加入 `room_test_004`。
4. 预期结果：
- 房间标签更新为 `room_test_004`。
- 不出现旧房间残留状态。

## 4. 回归检查
- 职业按钮切换仍然正常（剑纯/万花/五毒）。
- 画布点击准备、长按读条、短按打断逻辑未受影响。
- 页面在移动端尺寸下控件不重叠、可点击。

## 5. 常见问题排查
- 看不到“退出房间”按钮：
1. 确认打开的是 `TwoPlayers.html`。
2. 强制刷新（`Ctrl + F5`）。
3. 打开控制台检查是否有 `[room-ui]` 日志。
- 无法联机：
1. 检查 `ws_server.js` 是否在运行。
2. 检查浏览器控制台是否有 WebSocket 连接错误。
3. 确认访问地址与 `WS_URL` 对应主机一致。
